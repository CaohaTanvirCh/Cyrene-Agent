## 本地聊天模型接入

支持把聊天模型接入**本地 OpenAI 兼容服务**（Ollama / LM Studio / llama.cpp server 等），
无需云端 API Key 即可与本地小模型对话。

### 原理

复用现有的厂商适配（vendor-adapter）架构：新增一个「本地模型（Local）」预设，
走 OpenAI 兼容协议，指向本机的服务地址即可。API Key 为空时不发送鉴权头（本地服务通常不校验）。

### 使用方法（以 Ollama 为例）

1. 本机安装并启动 Ollama，拉取模型：
   ```bash
   ollama pull gemma3
   ollama serve
   ```
   Ollama 默认 OpenAI 兼容入口：`http://localhost:11434/v1`
2. 打开 **设置 → API 设置**，预设选择 **「本地模型（Local）」**。
3. 确认 baseUrl（默认 `http://localhost:11434/v1`），模型名填写你拉取的模型（如 `gemma3`）。
4. API Key **留空**即可，点「测试连接」确认连通，保存。

### 使用方法（以 LM Studio 为例）

1. LM Studio 里加载模型，打开 **Developer / Local Server**，点 **Start Server**。
   LM Studio 默认地址：`http://localhost:1234/v1`
2. 设置 → API 设置 → 预设选「本地模型（Local）」。
3. **把 baseUrl 改成 `http://localhost:1234/v1`**（默认预设是 Ollama 的 11434 端口）。
4. 模型名填 LM Studio 里加载的模型名（服务器页面顶部会显示）。
5. API Key 留空，测试连接后保存。

### 说明

- 本地模型能力参差不齐，思考/视觉能力默认保守关闭。
- 想切回云端 API：回设置把预设换成对应厂商即可。
- 局域网另一台机器跑的本地服务（如 `192.168.x.x`）也识别为本地地址，同样允许空 Key。
- 通过 Tailscale 组网访问另一台机器（`100.64.x` ~ `100.127.x` 网段）同样识别为本地，允许空 Key。

### 常见问题排查

**测试连接提示「需要输入 API Key」**
- 说明该地址未被识别为本地。本地/局域网/Tailscale 地址会自动放宽 Key 校验；
  公网地址仍需填 Key（可随便填一个非空字符串）。

**测试连接返回「连接成功但模型返回空内容」，或聊天永远返回空**
- 最常见原因：**baseUrl 漏了 `/v1`**。OpenAI 兼容端点是 `{base}/v1/chat/completions`。
  - LM Studio 应填 `http://<主机>:1234/v1`
  - Ollama 应填 `http://<主机>:11434/v1`
  - 程序现已能在你只填主机端口（无路径）时自动补 `/v1`，但填了错误路径不会纠正。
- 其次检查**模型名**是否与本地已加载的一致。

**跨机访问（Tailscale / 局域网）测试时 `fetch failed`**
- 多半是对端服务只监听 `127.0.0.1`，未对外开放。需要让本地服务监听 `0.0.0.0`：
  - **LM Studio**：Developer/Server 页把 "Serve on Local Network" 打开（或监听 `0.0.0.0`）。
  - **Ollama**：设置环境变量 `OLLAMA_HOST=0.0.0.0` 后重启服务。
- 再检查对端防火墙是否放行对应端口（如 1234 / 11434）。

**协作模式空回复 / 报「上下文超出模型可用长度」**
- 协作模式会携带完整人格 + 全部工具定义，prompt 很长（可能上万 tokens）。
  若本地推理服务的 context length 设得太小（如 8192），会超限导致模型返回空。
- 解决办法二选一：
  - **调大 context length**：LM Studio 加载模型时把 context length 调到 16384 或更高，重新加载。
    （注意：更大的上下文会占用更多显存/内存。）
  - **改用「日常聊天」模式**：不携带工具，prompt 短很多，小上下文也能跑。
- 程序现在会把这类「上下文超限」错误明确提示出来，不再是无声的空回复。

> 提示：本地小模型（尤其 7B~12B）在协作模式下由于 prompt 长、工具多，
> 推理会明显比云端慢（可能数十秒），这取决于运行模型那台机器的性能，属正常现象。

## 工作区目录

给 agent 一个「当前所在目录」的基准概念，让它更像 claude-code / opencode 那种明确 cwd 的工具，
而不是纯聊天。**工作区可选**：选了目录就是 agent 模式，不选就是纯聊天。

### 定位（软约束）

工作区是「默认基准目录」，不是牢笼：

- 文件工具收到**相对路径**时，以工作区为基准解析成绝对路径；仍支持**绝对路径**访问任意位置。
- `run_shell` 等未指定 cwd 时，默认在工作区下执行。
- 工作区当前目录会注入到模型的系统上下文，让它知道「现在在哪个目录」。
- 不设工作区（纯聊天模式）时，文件类工具回退到「必须给绝对路径」的原行为。

### 使用方法

- **选择目录**：聊天窗口顶部标题栏点 **📁 选择目录** 按钮，弹出系统目录选择框，选一个文件夹。
  选好后按钮显示目录名，鼠标悬停可看完整路径。
- **切换目录**：再次点击该按钮即可重新选。
- **清除目录**：点按钮上的 **✕**，回到纯聊天模式。
- 工作区选择会跨重启保留；多窗口之间自动同步。

### 权限

工作区是软约束，agent 能访问工作区以外的位置仍受**权限档位**约束
（设置 → 昔涟 → 本地文件权限：只读 / 指定目录 / 每次审批 / 完全访问）。

## 思考过程显示

支持带思考能力的模型（如 DeepSeek 的 reasoning）把**推理过程**展示出来，默认折叠。

### 使用方法

- 默认开启。模型回复中若包含思考过程，会在回复气泡上方显示一个 **💭 思考过程** 折叠块，
  点击展开查看。
- **开关**：设置 → 通用设置 → **显示思考过程**。关闭后不再显示思考块。
- 思考过程为瞬态，不写入聊天历史。

## 流式输出

让思考与答案「边生成边显示」，而不是整段一次性蹦出来（类似 DeepSeek 网页 / opencode 的体验）。

### 适用范围

- **仅 OpenAI 兼容厂商生效**（DeepSeek / 本地模型 / Kimi / Qwen / GLM 等）。
- MiniMax（Anthropic 协议入口）即使开启也走非流式路径（其多轮机制更特殊）。

### 使用方法

- 默认开启。开启后：
  - 思考过程实时逐字滚动显示。
  - 答案实时逐字流式输出。
- **开关**：设置 → 通用设置 → **流式输出**。
- 关闭后回到「整段生成完再一次性显示」的稳定行为。

### 说明

流式作为独立分支实现，与原非流式路径并存；关闭开关即完全回到原行为。
若流式下出现异常，可先关闭此开关排查。

## 动态背景开关

聊天 / 通话窗口默认有漂浮粒子动画背景。动画会持续占用性能，可一键关闭。

### 使用方法

- **开关**：设置 → 通用设置 → **动态背景**。
- 关闭后聊天窗、通话窗的粒子动画停止并清空画面，降低性能占用。
- 一个开关同时控制所有窗口。
